PHASE 1 - PRE-TEST EXPECTATIONS: FOURIER / JPEG-GHOST ENGINE
Written 2026-08-18, before the diagnostic run.

DISCLOSURE FIRST, so nothing below can be mistaken for a blind prediction.
One timing probe was run before this file was written, because the engine's
per-image cost had to be measured to size the run at all. It analysed
campic.jpeg (authentic) and returned raw_score=1.0000, probability=1.0000,
confidence=0.2236, is_reliable=True, D_max=0.6797 at q2=6, grid shift (0,4),
with 289 of 320 combinations rejected as degenerate. That single result was
known when the predictions below were written. The other five images were not
run first.

STEP 1.1 - CORE ENGINE CAPABILITY (from the SKILL)

Property measured: a double-quantization artefact in the 8x8 block-DCT
domain. The engine recompresses the whole image at a sweep of candidate
quality factors q2 and differences against the original (Azarian-Pour Eq. 8).
A block already quantized at a given q2 loses little further information, so
its difference energy hits a LOCAL MINIMUM there - the "ghost".

Signal present in FAKE, absent in REAL: two DIFFERENT ghost qualities in one
frame. A spliced region carries its own original q0 while the host background
carries q1, so after the min-max normalisation of Eq. 9 the pasted region
collapses toward zero at q2=q0 while the background stays high. Eq. 10's
Bhattacharyya distance measures how separable those two populations are.

Signal present in REAL: one single ghost quality everywhere. The whole frame
shares one compression history, so the normalised map should have no spatially
coherent minority region at any q2 - the map is unimodal at every candidate
quality, and every candidate should be rejected by the validity test.

Computation producing raw_score: D_max = max over all (q2, dx, dy) of Eq. 10's
B; then raw_score = clip(D_max / Th, 0, 1) with Th = 0.19 - the SKILL's own
recommended normalisation, so raw_score = 1.0 marks exactly the paper's
forged/authentic boundary.

Range meaning: raw_score < 1.0 means D_max below the paper's threshold, i.e.
REAL-leaning. raw_score = 1.0 means D_max at or beyond it, FAKE-leaning - but
note that clipping makes the score SATURATE, so 1.0 conveys no magnitude.

HARD DIRECTIONAL CONSTRAINT the SKILL states outright: the method works only
when the spliced region's original quality q0 is LOWER than the re-save
quality q1, and "does not resolve the reverse case". Sensitivity exceeds 95%
only once q1-q0 > 22 and fades to nothing as the gap closes. q0 is exactly
what is unknown, so this is untestable per image.

CASE 1 - REAL IMAGES (campic.jpeg, campic2.jpeg)
  Expected probability range : 0.0 - 0.3
  Expected raw_score range  : 0.0 - 0.5 (D_max well below Th = 0.19)
  Expected is_reliable      : True. Both are JPEG, so the container gate
                              passes; nothing else in the checker can fail on
                              a normal photograph.
  Expected evidence_map     : an overlay with no coherent flagged region, and
                              flagged_regions empty because D_max should not
                              clear Th.
  Signal that should be ABSENT: any spatially coherent minority region in the
                              normalised difference map at any candidate q2.
  Most likely failure mode  : ALREADY OBSERVED on campic.jpeg - Eq. 10's first
                              term is a variance-MISMATCH term that rewards any
                              unequal-spread split, so cutting a unimodal noise
                              map anywhere manufactures a large B. The build
                              phase already had to add three validity
                              constraints for exactly this, and the probe shows
                              they are not sufficient. I expect campic2.jpeg to
                              false-alarm the same way.

CASE 2 - FAKE / MANIPULATED IMAGES (fake .jpeg, fake.jpeg)
  Expected probability range : 0.6 - 1.0
  Expected raw_score range  : 1.0 (saturated) if the splice is detected
  Expected is_reliable      : True, same reasoning as Case 1.
  Expected evidence_map     : the winning combination's binary tamper mask
                              over the pasted region - this engine is the only
                              one in this system whose localisation the SKILL
                              itself calls "literally a segmented binary tamper
                              mask".
  Signal that should be PRESENT: a coherent minority region whose difference
                              energy dips at one q2 while the background does
                              not.
  Most likely failure mode  : the provenance of these files is unknown. If they
                              are AI-generated or re-saved at a HIGHER quality
                              than their source, the SKILL says the method
                              cannot resolve them at all. Worse, given the
                              Case 1 probe, a "correct" FAKE call here may be
                              the same false-positive mechanism firing on a
                              genuinely fake image - a right answer for the
                              wrong reason, which is why the ungated probe
                              records WHY each candidate was kept or rejected.

CASE 3 - AI-GENERATED IMAGES (gen.jpeg, genratedimage.jpeg)
  Expected probability range : uncertain. An AI image saved once as JPEG has
                              ONE compression history, exactly like an
                              authentic photograph, so on the engine's own
                              premise it should look REAL. Any FAKE call here
                              is the false-positive mechanism, not detection.
  Expected is_reliable      : True (the container gate is all that applies).
  Is AI detection in SKILL scope: NO. The SKILL's mechanisms are resampling
                              periodicity from geometric transformation and
                              double compression from splicing. Neither exists
                              in a natively generated image. The word
                              AI-generated appears nowhere in the SKILL, and
                              its "manipulation types detected best" list names
                              only geometric splicing/resizing and
                              lower-quality-into-higher-quality splices.
  If NO, what will it do    : score whatever its segmentation happens to find,
                              i.e. report on the false-positive mechanism only.
  Most likely failure mode  : engine is not designed for this case at all.

NOTE ON THE AI FOLDER: the folder named in the specification does not exist on
disk. The two files inside the fake-images folder whose names denote AI
generation (gen.jpeg, genratedimage.jpeg) stand in for Case 3. Their AI
provenance is inferred from their filenames, not verified.
